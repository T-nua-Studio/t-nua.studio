# План миграции T-NUA на Cloudflare

Статус: отложено до завершения предварительных изменений сайта.

Целевая архитектура:

```text
GitHub
  └── HTML, CSS и JavaScript
          │
          ▼
Cloudflare Pages
  └── t-nua.com

Cloudflare R2
  └── media.t-nua.com
      ├── videos/
      ├── images/
      ├── project-media/
      └── 3d/
```

Cloudflare Stream на первом этапе не используется.

## 1. Зафиксировать исходное состояние

- Проверить все страницы и ссылки.
- Измерить показатели Lighthouse/PageSpeed.
- Записать время и объём первой загрузки главной страницы.
- Проверить мобильную версию.
- Сохранить текущие DNS-записи.
- Создать отдельную Git-ветку для миграции.

Эти данные понадобятся для объективного сравнения скорости и безопасного отката.

## 2. Подключить домен к Cloudflare

1. Создать аккаунт Cloudflare.
2. Добавить домен `t-nua.com`.
3. Проверить импортированные Cloudflare DNS-записи.
4. Вручную сверить:
   - записи сайта;
   - MX;
   - SPF;
   - DKIM;
   - DMARC;
   - записи сторонних сервисов и подтверждения домена.
5. Заменить nameservers у текущего регистратора на выданные Cloudflare.

Переносить регистрацию домена в Cloudflare необязательно. Домен можно продолжать оплачивать у текущего регистратора.

## 3. Создать проект Cloudflare Pages

1. Подключить GitHub-репозиторий `T-nua-Studio/www.t-nua.studio`.
2. Выбрать production-ветку `main`.
3. Настроить автоматическую публикацию после push.
4. Сначала опубликовать сайт на техническом адресе вида `tnua.pages.dev`.
5. Не переключать основной домен до полной проверки preview-версии.

## 4. Подготовить Cloudflare R2

1. Создать Standard-бакет `tnua-media`.
2. Подключить production-поддомен `media.t-nua.com`.
3. Организовать файлы:

```text
videos/
  hero/
  projects/
  blog/

images/
  projects/
  clients/
  posters/

3d/
icons/
```

4. Проверить MIME-типы:

```text
.mp4   video/mp4
.webp  image/webp
.jpg   image/jpeg
.glb   model/gltf-binary
```

5. Настроить длительное кеширование для версионированных файлов.

## 5. Перенести медиа в R2

В R2 необходимо перенести:

- MP4 и MOV;
- крупные изображения;
- постеры видео;
- клиентские изображения;
- при необходимости GLB-модель.

На момент составления плана семь видео превышают лимит Cloudflare Pages в 25 МиБ:

| Файл | Размер |
|---|---:|
| `assets/videos/cockaigne/untitled_s2-1080p.mp4` | 76,9 МБ |
| `assets/videos/cockaigne/untitled_s1-1080p.mp4` | 75,7 МБ |
| `assets/videos/cockaigne/untitled_s3-1080p.mp4` | 68,6 МБ |
| `assets/videos/Yad-Morddechai-Shavuot-CGI.mp4` | 39,8 МБ |
| `assets/videos/Ipod_motion.mp4` | 30 МБ |
| `assets/videos/TISSF2024.mp4` | 27 МБ |
| `assets/videos/Brainbox.mp4` | 26,4 МБ |

Перед загрузкой следует привести имена объектов к единому стилю: нижний регистр, дефисы вместо пробелов, без специальных символов.

## 6. Заменить ссылки на медиа

Пример:

```html
<video src="assets/videos/Brainbox.mp4">
```

после миграции:

```html
<video
    src="https://media.t-nua.com/videos/projects/brainbox.mp4"
    poster="https://media.t-nua.com/images/posters/brainbox.webp"
    preload="metadata"
    playsinline>
```

Обновить ссылки:

- в `index.html`;
- во всех страницах `projects/`;
- в блоге;
- в CSS;
- в JavaScript;
- в SEO-метаданных;
- в `sitemap.xml`, если в нём появятся ссылки на медиа.

После замены автоматически проверить доступность всех URL.

## 7. Добавить минимальный процесс сборки

Добавить кроссплатформенный скрипт, который создаёт каталог `dist`.

```text
Исходный репозиторий
        ↓
Скрипт подготовки
        ↓
dist/
        ↓
Cloudflare Pages
```

В `dist` должны попадать:

- HTML;
- CSS;
- JavaScript;
- небольшие локальные ресурсы;
- `robots.txt`;
- `sitemap.xml`;
- необходимые служебные файлы.

Тяжёлые медиа не должны попадать в результат публикации Pages.

## 8. Оптимизировать загрузку видео

- Для видео вне первого экрана использовать `preload="none"`.
- Для Hero использовать `preload="metadata"` или небольшой оптимизированный ролик.
- Добавить WebP-постеры.
- Загружать видео при приближении к viewport или по действию пользователя.
- Не запускать одновременно несколько роликов.
- Не использовать MOV и HEIC для веб-доставки.
- Сжать слишком тяжёлые MP4.
- Сохранять оригинальные мастер-файлы в отдельном архиве.

Для фонового Hero-видео желательно подготовить версию размером примерно 3–10 МБ, если это позволяет требуемое качество.

## 9. Проверить preview-версию

Проверить:

- главную страницу;
- все страницы проектов;
- блог;
- мобильную навигацию;
- фильтры проектов;
- Hero-видео;
- Three.js и GLB-модель;
- воспроизведение и перемотку видео;
- нестандартные пропорции;
- отсутствие CORS-ошибок;
- консоль браузера;
- внутренние и внешние ссылки;
- favicon;
- Open Graph;
- schema.org;
- Lighthouse Performance, SEO и Accessibility;
- Safari и iPhone;
- поведение `playsinline` и autoplay.

## 10. Переключить основной домен

1. Подключить `t-nua.com` к Cloudflare Pages.
2. Подключить `www.t-nua.com`.
3. Выбрать канонический вариант.
4. Настроить постоянный редирект второго варианта на основной.
5. Проверить HTTPS.
6. Оставить GitHub Pages как временный резерв.

Переключение выполнить в период низкой посещаемости.

## 11. Проверить production после переключения

- Повторить все smoke-тесты.
- Проверить DNS из нескольких регионов.
- Проверить почту.
- Проверить HTTPS и редиректы.
- Проверить Google Analytics.
- Проверить загрузку медиа с `media.t-nua.com`.
- Сравнить Lighthouse и фактический объём первой загрузки с исходными показателями.
- Несколько дней отслеживать ошибки и расход R2.

## 12. Очистить и документировать проект

После подтверждения стабильной работы:

- удалить тяжёлые медиа из текущей рабочей версии Git;
- сохранить оригиналы минимум в двух независимых местах;
- обновить `README.md`;
- обновить инструкции публикации;
- пометить старые инструкции GitHub Pages как устаревшие или удалить их;
- описать правила загрузки новых проектов и медиа.

Переписывание старой Git-истории с удалением медиа выполнять только как отдельную операцию после резервного копирования. Для запуска сайта на Cloudflare это не обязательно.

## Ожидаемая стоимость

При текущем объёме и обычной посещаемости:

```text
Cloudflare Pages   $0
Cloudflare R2      $0 в пределах бесплатных лимитов
Cloudflare Stream  не используется
Домен              оплачивается как сейчас
```

Бесплатный уровень R2 включает 10 ГБ хранения, 1 миллион операций записи и 10 миллионов операций чтения в месяц. Исходящий трафик R2 не тарифицируется.

## Ожидаемое влияние на скорость

Сам перенос HTML, CSS и JavaScript с GitHub Pages на Cloudflare Pages может дать небольшой или умеренный выигрыш. Основное ускорение должно прийти от:

1. переноса медиа в R2;
2. загрузки видео по требованию;
3. уменьшения Hero-видео;
4. использования постеров;
5. корректного кеширования;
6. исключения тяжёлых видео из первой загрузки.

Главные показатели для сравнения до и после миграции:

- Largest Contentful Paint;
- First Contentful Paint;
- Total Blocking Time;
- объём первой загрузки;
- время загрузки Hero;
- объём загруженного видео до взаимодействия пользователя;
- показатели на мобильном соединении.

## Условия начала миграции

Миграцию начинать только после завершения запланированных предварительных изменений сайта и отдельного подтверждения.
