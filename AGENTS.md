# Инструкции для будущих изменений сайта

## Архитектура

- Сайт — статический многостраничный HTML-проект на vanilla HTML/CSS/JavaScript; сборщика и общего runtime-layout нет.
- Главная страница находится в `index.html`, статьи — в `blog/`, кейсы — в `projects/`.
- Общие стили находятся в `css/`, общая логика — в `js/`.

## Как добавлять новые страницы

1. Выбрать ближайший по структуре существующий HTML-файл и сохранить его семантическую структуру, навигацию, footer, ссылки на CSS и относительные пути к ресурсам.
2. Создать страницу в подходящей директории (`/`, `blog/` или `projects/`) с уникальными `title`, `meta description`, canonical/OG-метаданными, если они нужны для типа страницы.
3. Добавить страницу в навигацию или sitemap только если это соответствует задаче; не менять существующие URL без явной необходимости.
4. Подключить общие скрипты в конце `body` с корректными относительными путями.
5. Перед закрывающим `</body>` добавить ровно один официальный HubSpot Tracking Code:

   `<script type="text/javascript" id="hs-script-loader" async defer src="//js-eu1.hs-scripts.com/146755814.js"></script>`

   Не добавлять HubSpot в компоненты, которые могут монтироваться повторно, и не создавать второй элемент с `id="hs-script-loader"`.
6. Не подключать необязательные аналитические/медиа-сервисы в обход `js/privacy.js` и существующего cookie consent.
7. Не добавлять CSP meta-тег без проверки серверных заголовков. Если CSP появится, разрешить только необходимые HubSpot-домены в соответствующих директивах, сохранив остальные ограничения.

## Проверка перед передачей

- `npm run build`
- `npm run check:language`
- Поиск `id="hs-script-loader"` по всем HTML-файлам: ровно один на страницу.
- Проверка сайта через локальный static server и DevTools: запрос `js-eu1.hs-scripts.com/146755814.js` должен вернуть `200`/`304`, а в Console не должно быть новых ошибок.
- Проверить главную, blog, project, privacy, cookies и accessibility страницы.
